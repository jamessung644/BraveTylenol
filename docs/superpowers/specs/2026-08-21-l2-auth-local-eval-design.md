# L2 인증 경로 및 로컬 평가 업그레이드 설계

## 목표

정상 완주한 `09b01df` 서버 계약과 fallback 안정성은 유지하면서, 평가 요청의
임의 Bearer 값이 실제 Lunit 키를 가리는 문제를 제거한다. 제출 전 로컬에서
CoEval과 같은 동시성 16 조건으로 L2 성공률과 지연시간을 측정하고, 검증 결과가
기준을 만족할 때만 제출 브랜치에 반영한다.

## 확인된 원인

현재 구현은 요청 Bearer를 `LUNIT_FM_API_KEY`보다 먼저 선택한다. 로컬 재현에서
실제 환경변수 키가 있어도 임의 Bearer 헤더가 들어오면 L2가 즉시 실패하고 정적
fallback을 반환했다. 반대로 실제 키를 사용한 L2 직접 호출은 12.82초에 정상
응답했고, 동시성 16 재현에서는 15건이 L2 답변, 1건이 fallback이었다.

## 인증 선택 규칙

1. `LUNIT_FM_API_KEY` 환경변수가 `lunit_` 접두사를 가진 유효한 값이면 가장 먼저
   사용한다.
2. 환경변수가 없을 때만 요청 Bearer를 검사하고, `lunit_` 접두사를 가진 값만
   사용한다.
3. 빈 값, 예제 값, 개행 포함 값, 과도하게 긴 값, 다른 형식의 Bearer는 L2 키로
   사용하지 않는다.
4. 키의 원문, 일부 문자열, 해시를 로그·응답·테스트 결과에 남기지 않는다.
5. 로컬 키는 `/tmp/bravetylenol-lunit-key`에서 셸 환경변수로만 전달하며 저장소와
   Docker 이미지에는 포함하지 않는다.

## L2 요청 및 fallback

- 요청당 L2 호출은 한 번만 수행하며 재시도하지 않는다.
- 제한시간은 30초로 늘린다. CoEval의 요청 제한 180초보다 충분히 짧고, 실측한
  동시성 16 응답 범위 약 11~19초를 수용한다.
- L2가 정상적인 비어 있지 않은 텍스트를 반환하면 그 답변을 OpenAI 호환 응답으로
  전달한다.
- 인증 부재, 시간초과, HTTP 오류, 잘못된 JSON, 빈 응답 등은 기존 정적 한국어
  fallback과 HTTP 200 응답으로 복귀한다.
- 질문, 답변, 헤더, 키는 기록하지 않는다. 프로세스 내부에는 성공·인증 없음·
  시간초과·HTTP 오류·잘못된 응답의 누적 개수만 보관할 수 있다.

## 로컬 평가

검증은 실제 비밀 값을 출력하지 않고 다음 순서로 수행한다.

1. 단위 테스트로 환경변수 우선순위, 올바른 Bearer fallback, 잘못된 Bearer 무시,
   30초 제한, 오류 시 HTTP 200을 검증한다.
2. Docker 이미지를 새로 빌드하고 비루트 사용자, health endpoint 및 OpenAI 응답
   스키마를 확인한다.
3. 실제 키를 컨테이너 환경변수로만 주입한 뒤 동시성 16 요청을 실행한다.
4. L2 성공률, fallback 수, p50·p95·최대 지연시간만 출력한다.
5. 최소 통과 기준은 16건 중 15건 이상 L2 성공, HTTP 오류 0건, 요청별 35초 미만,
   모든 응답의 비어 있지 않은 assistant content이다.
6. 정확한 HealthBench 점수는 별도의 judge credential이 있어야 하므로, 이 단계의
   로컬 게이트는 L2 사용률과 API 성능을 검증한다. 필요하면 이후 공개 validation
   일부를 별도 비용·키로 채점한다.

## 브랜치 및 배포

- 구현 브랜치: `upgrade/l2-auth-local-eval`
- 안정 기준: `main`의 `3f9c434`
- 로컬 게이트가 실패하면 제출 브랜치를 변경하지 않는다.
- 게이트가 성공하면 원격 제출 브랜치의 최신 이력을 다시 가져와 강제 푸시 없이
  병합하고 `lunit/hackathon-submission`에 푸시한다.
- `main` 반영은 실제 대시보드 평가 결과가 개선된 뒤 별도로 수행한다.

## 제외 범위

이번 단계에서는 MCP, RAG, reranker, context compression, 다중 L2 재시도, 외부
OpenAI 모델을 추가하지 않는다. 먼저 실제 L2 답변이 평가기에 전달되는 경로를
확립한 뒤 다음 단계에서 품질 개선을 진행한다.
